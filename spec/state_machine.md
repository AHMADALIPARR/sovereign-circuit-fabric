# Deterministic Circuit State Machine

## States

| State      | Meaning |
|------------|---------|
| FREE       | No resources allocated; identifier may be reused after release |
| REQUESTED  | Setup request received; admission decision pending |
| ADMITTED   | Policy accepted the request; reservation not yet performed |
| RESERVED   | Bandwidth and buffer resources held; not yet installed in datapath |
| INSTALLED  | Forwarding entries written; not yet carrying user traffic |
| ACTIVE     | Carrying data; accounting active |
| DRAINING   | Teardown initiated; in-flight data allowed to complete |
| RELEASED   | All resources returned; final accounting event emitted |
| FAILED     | Terminal failure state; resources must still be released |

## Legal Transitions

```
FREE       --request-->          REQUESTED
REQUESTED  --admit-->            ADMITTED
REQUESTED  --reject-->           FREE
REQUESTED  --timeout-->          FREE
ADMITTED   --reserve-->          RESERVED
ADMITTED   --fail-->             FAILED
RESERVED   --install-->          INSTALLED
RESERVED   --fail-->             FAILED
INSTALLED  --activate-->         ACTIVE
INSTALLED  --fail-->             FAILED
ACTIVE     --drain-->            DRAINING
ACTIVE     --fail-->             FAILED
DRAINING   --release-->          RELEASED
DRAINING   --fail-->             FAILED
FAILED     --release-->          RELEASED
RELEASED   --recycle-->          FREE
```

All other transitions are illegal.

## Events

- `request(cid, src, dst, bw, prio, qos, tariff)`
- `admit(cid)` / `reject(cid, reason)`
- `reserve(cid)`
- `install(cid, labels, ingress, egress)`
- `activate(cid)`
- `drain(cid)`
- `release(cid)`
- `fail(cid, reason)`
- `timeout(cid)`
- `recycle(cid)`

## Determinism Requirements

1. Every transition is triggered by exactly one explicit event.
2. State change and outputs (resource allocation, table writes, accounting events) are atomic with respect to the circuit identifier.
3. Concurrent events on the same circuit are serialized by the owning BEAM process.
4. Timeouts are generated by a single timer ownership model; only the owning process may cancel or fire the timer.

## Invariants (must hold after every transition)

- A circuit in FREE has zero reserved bandwidth and no table entries.
- A circuit in RESERVED or later has positive reserved bandwidth until RELEASED.
- No two circuits may share the same (NamespaceID, CircuitID) while both are non-FREE.
- Total reserved bandwidth on any link never exceeds link capacity.
- RELEASED implies a final accounting event has been generated exactly once.
